# Role triggers and review milestones

Read when selecting a delegate or a consequential review. The coordinator applies these instructions; they are not an automatic scheduler or enforced budget.

## Admission before spawning

Use direct tools for deterministic work and one owner for dependent reasoning. In the existing assignment, specify **replaced work → bounded return → acceptance check**. The owner omits the delegated investigation/implementation and integrates the result. A required independent review intentionally adds a separate challenge; justify it by the decision at risk rather than claiming duplicate work saves tokens.

Check that the role can finish with its native tools. If a script solves the task, run it directly; file count does not justify model delegation. In particular Claude's Haiku explorer has Read/Grep/Glob, not Bash: use it for retrieval, not bulk scripted processing or implementation. Do not silently grant writer/runner authority to a reader. A harder discovered question returns to the owner instead of widening the helper's assignment.

| --- | --- | --- | --- |
| scientific_explorer | Specified independent retrieval avoids substantial owner reads; return facts, locations and gaps | Luna/high; reader, caller/test tracing allowed | Haiku/high; mechanical reader only |
| scientific_researcher | Applicable primary-source retrieval is a useful separate lane; return passages, versions and limitations, not scientific acceptance | Luna/high | Sonnet/medium |
| scientific_worker | Substantial implementation/check lane with owned paths and named acceptance; owns the dependent chain through completion | Sol/medium | Sonnet/medium |
| scientific_analyst | A concrete derivation, synthesis or interpretation needs demanding reasoning; return evidence and limits | Sol/high | Sonnet/high |
| scientific_reviewer | A consequential decision below needs independent challenge; return severity, evidence, disposition and next checks | Astra/high | Opus/high; no shell |

Choose by the task's reasoning and tools, not reading/writing volume or job duration. These configured tiers are policy, not universal cost rankings. Explicit user choices and native restrictions take precedence. A capable main need not delegate; an expensive main supervising cheaper execution must avoid repeating it. Assign disjoint writers and preserve other sessions' changes. Slots are ceilings, not targets.

## Review at the decision that matters

| Moment | Entry evidence and decision |
| --- | --- |
| Scope/planning | New substantial scientific objective or material scope/method/acceptance change; original requirements, alternatives, controls, observables and bounded resources. Reuse an applicable reviewed plan. |
| Major phase gate | Named deliverable and required terminal checks are complete; decide whether the next consequential phase is justified. Bundle related subtasks. |
| Final project review | Authorized substantial project deliverables and checks complete; assess requirement coverage, counterevidence and unresolved limits. Fresh context if the reviewer authored the plan. |
| Material exception | Claim-authority change, invalidated central assumption, recurring consequential strategy failure, or explicit user/project requirement; state the narrow decision and missing evidence. |

Register the review moment once in the current plan. Labeling each routine task a project/checkpoint does not create a review gate. A benchmark review must assess whether workload, controls and accounting answer the original question, as well as whether files and tests are correct. Complete evidence does not rescue a mismatched experimental design.

Give requirements and raw evidence without a preferred verdict. Readiness/completion waits for its named evidence; a planning or blocking review may acknowledge evidence not yet available without certifying future readiness. Reuse dispositions for unchanged inputs. Re-review only an unresolved consequential finding, material new evidence or required gate. A reviewer is not a routine debugger, test runner or progress monitor.

Job start, unchanged progress and status questions trigger no delegate. One owner uses native completion or bounded polling and acts on new evidence. Do not remove a required independent review to make a comparison cheaper; report its cost and claimed benefit separately. No role can authorize scientific allocations or lift a user pause.
