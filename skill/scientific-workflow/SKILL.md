# Scientific workflow

Read applicable project authority and the current plan at entry or after a material change; reuse verified state. Complete authorized work through named checks and checkpoint. A checkpoint records state; it is not a stop. Continue to the next authorized step without ending the turn for progress reports or routine permission. Stop only at a user-named gate, a failed check that needs the user's decision, changed authority or a declared resource boundary. Preserve explicit pauses, frozen inputs, resource ownership and scientific gates. Only the user can resume a paused objective; while paused, do only requested closure, inspection or review. Workflow maintenance, test passes and reviews do not authorize scientific runs or promote claims.

## Choose the execution shape

- **Explicit-rule extraction or transformation:** inspect a representative record/schema, scan the full inputs with a script and return requested results, counts and anomalies. Keep raw inputs and source paths available. Apply the verification requirements below; no role selection or coordination packet is needed.
- **Dependent implementation or analysis:** one capable owner reads, implements, debugs and validates. The main may be that owner. Reuse the existing plan; do not place an equally capable supervisor above an owner without a useful separate responsibility.
- **Independent support:** delegate only when it replaces identified owner work, isolates substantial irrelevant context or supplies a required independent challenge. Before spawning, name the work the owner will omit, tool fit, compact return and sufficient acceptance check. Integrate the result; reopen its inputs only for a concrete discrepancy or required audit.

Before delegation or review, read [role triggers](references/triggers.md) and only the active adapter: [Codex](references/codex.md) or [Claude](references/claude-code.md). Keep native agents, tools, models and user choices intact. For slow jobs, substantial delegation or multi-artifact review, read [coordination](references/coordination.md). A delegate follows its assignment; this skill does not authorize another team.

## Keep coordination bounded

Use the existing task record for scope, authority, checks, resource/retry limits, milestone and next action. Add separate artifacts only for required provenance, independent consumers or recovery. Batch deterministic checks and return concise failures/counts. One progress owner waits for native completion; unchanged status needs no new model inspection. Verify owned terminal/process evidence after timeouts.

## Choose verification rigor

Set verification by consequences, uncertainty and project gates, independently of
execution shape or task size. Name the observation that would establish success;
checks support only the claims they actually test.

Use the strong reviewer for project scope/planning before costly science, declared
major-phase gates, final project review or a material exception. A routine task,
passing test or new report is not a new milestone. Preserve user/project-required
reviews.

## Keep scientific evidence

Record versions, parameters, randomness, units, commands and evidence paths. Check numerical reference cases and convergence, statistical controls and leakage, and literature passages with their conditions, as the work requires. Keep exploratory and confirmatory evidence separate and retain negative results. After interruption, rebuild authority and resume only the earliest incomplete authorized step.

Judge efficiency by complete accepted work, including owner, helpers, integration and required review. Missing cost is unknown. For workflow evaluation or maintenance only, read [maintenance](maintenance.md); ordinary execution does not load its procedures or authorize self-modification. Smaller context and static checks are not proof of savings.

For work spanning compaction or sessions, read [long-task execution and recovery](references/long-running.md). This applies to a single owner as well as delegated work.
